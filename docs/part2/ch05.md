# 第5章 · SRE 招聘、培养与职业发展

> [!INFO] 出处

**一句话概括**：把 SRE 能力体系拆成三段——招聘（双画像 + 特雷诺曲线）、培养（从非正式学习到 SRE EDU 正规项目的全景培训矩阵）、职业发展（广度/主动性/协作三大成功要素与 IC 技术领导力路径），并论证人才留存才是可靠性的隐藏杠杆。

## 核心概念

| 概念 | 术语（EN） | 说明 |
|---|---|---|
| 角色画像 / 职业阶梯 | Role Profile / Career Ladder | 界定岗位与资历级别的期望；Google 为 SRE 设 SRE-SWE 与 SRE-SE 两套画像 |
| 特雷诺曲线 | Treynor Curve | 系统工程技能与软件工程技能的可接受组合光谱；混合型（hybrid）候选人落在其覆盖区 |
| 非抽象大型系统设计 | Non-Abstract Large System Design (NALSD) | 要求给出切实数值估算并在可靠性、成本、难度间权衡的系统设计面试轮 |
| 面试架构 | Interview Slates | 多套并行的面试组合配置，防止以特定传统背景定向淘汰候选人 |
| 冒名顶替综合征 | Imposter Syndrome | 新人怀疑自身能力的普遍心理；导师制与结构化培训是主要对抗手段 |
| 自生自灭 | Sink or Swim | 无指导无培训、任凭新人摸索的模式；滋生焦虑、挫败与人员流失 |
| 入门项目 | Starter Project | 为新人挑选的实践项目：有用、自包含、时限合理、不在关键路径上 |
| 影子跟随 / 反向影子跟随 | Shadowing / Reverse Shadowing | 新人跟随资深工程师值班操作 / 资深在一旁观察新人独立操作 |
| 厄运之轮 | Wheel of Misfortune | 故障角色扮演式模拟演练，在安全环境中训练排障与应急技能 |
| 故障破坏场景 | Breakage Scenarios | 在专用培训环境中人为注入故障，学员三人一组完成分流、缓解与彻底解决 |
| 轮值值班学习清单 | On-Call Learning Checklist | 条目式清单，列明加入轮值前必须掌握的技术、系统与核心概念 |
| ADDIE 模型 | ADDIE Model | 分析→设计→开发→实施→评估的教学设计经典流程 |
| "学员应能够" | A Student Should Be Able To | 用行为动词描述培训后可观察行为的目标框架，可验证培训效果 |
| 年度教育周 | Annual Week of Education (AWE) | 面向可靠性主题的一周线上学习盛会，兼作培训材料更新的倒逼机制 |
| T 型专长 | T-Shaped Expertise | 既有某一领域深度、又具备跨系统广度的人才结构 |
| 内部流动性 | Mobility | 鼓励在 SRE 组织内部转岗而非离职，留住专业能力并传播知识 |

## 关键论点

1. **招聘是双重筛选**：技术功底（编码、系统设计、故障排查）只是入场券；文化契合与思维模式——对琐事容忍度极低、求知欲强、"拒绝混蛋（No jerks）"——同等重要甚至更关键。
2. **两套画像 + 一条曲线**：SRE-SWE 沿用研发流程、偏重数据结构与算法；SRE-SE 更重系统知识与 NALSD；特雷诺曲线界定两种技能组合的可接受光谱，让多元背景各得其所。
3. **流程即第一印象，速度是硬指标**：从提交申请到录用通知超过约 40 个自然日，候选人放弃率明显上升；决策者应看重长处与增量价值，而非寻找淘汰借口；面试官评估与招聘师决策分离以保证标准一致。
4. **应届生 SRE 完全可行且可规模化**：爱尔兰项目由志愿者以 20% 时间项目驱动，7 年间招聘人数增长一个数量级，且收益大头在不到两年内显现；实习生转正是关键指标，进研发或 PM 岗也算胜利。
5. **培训是投资不是成本**："自生自灭"滋生焦虑、冒名顶替综合征与流失；培训的 ROI 可以量化——上手期缩短、离职率下降（附录 A 给出完整算例），好口碑还能反向降低招聘成本。
6. **按组织规模与增长速度选型**：自学 → 结对伙伴制 → 专题授课 → 系统化培训，构成投入由低到高的连续光谱；规模小而增长快的组织从入职培训中获益最多，同时切勿忽视在职员工的持续进修。
7. **用实证研究驱动培训内容**：Google 以 MaxDiff 等方法测定各资历级别的技能权重；核心胜任力五项——技术专长、问题解决、事故响应、沟通与协作、适应力与持续学习；技能重心随资历从响应型演进到战略引领型；生成式 AI 时代产品管理技能愈发重要。
8. **把培训项目当生产服务来运营**：SRE 原则同样适用于培训本身——自动化与自导式交付曾把净推荐值提升 30 个百分点、覆盖 95% 目标受众；"就绪轮值使命"（On-Call Ready）自助技术栈把参与人数抬到理论上限的 5 倍。
9. **职业成功三要素**：广度（T 型专长并保持一线手感：轮值、事故响应、亲自动手）、主动性（初级推动团队级改进，资深在组织层面洞察并推动跨团队变革）、团队协作（消除知识孤岛、个人英雄主义与工作壁垒等反模式）。
10. **留存是最大的杠杆**：培养一名能值班的 SRE 长达一年，资深工程师转型也要一年以上；"希望不是一种策略"——用 N+1 储备、灵活轮值、内部流动性留人；成员转岗研发同样是胜利，因为他把可靠性理念带了过去。

## 值得记住的数字

- **约 40 天**：招聘流程超过这个自然日数，候选人放弃率明显上升——先优化流程，别只盯简历吞吐量。
- **一个数量级 / 两年**：7 年间应届生招聘人数的增长幅度；招聘收益的大头在不到两年内显现。
- **20% / 1~8 小时**：志愿者项目占用员工时间的上限（每周至多一天）；爱尔兰项目每位志愿者每季度的投入区间。
- **1,000 人 / +30 pp / 95% / 5 倍**：SRE EDU 入职培训的理论年容量上限；自导式自动化交付带来的 NPS 增幅；目标受众完成率；"就绪轮值使命"自助化后的参与人数提升倍数。
- **50%**：Google 将运维工作的时间占比上限限定在此，防止团队被琐事吞噬。
- **一年（甚至更久）**：初级 SRE 胜任生产轮值的准备周期；资深软件工程师融入 SRE 角色所需时间——因此人员流失成本极高。

## 方法论速览

**高效培训内容设计（ADDIE + 行为目标）**：分析（受众及其需求）→ 设计（用"学员应能够……"的行为动词写目标，梳理 SME 名单，编写类似软件设计文档的教学设计文档作为单一真实来源）→ 开发（围绕目标模块化组织，与目标无贡献的素材坚决删）→ 实施（先"培训讲师培训"，再排期推广）→ 评估（保持紧凑且迭代的反馈循环）。

**SRE EDU 入职培训的试金石法则**：① 这是入职两周的新员工必须了解的内容吗？② 若是，它是否比当前讲授的某项内容更重要（腾出时间就得挤掉什么）？核心不是讲座灌输（"狂饮消防栓之水"），而是一系列实战性质的故障破坏场景：学员三人一组，对被故意注入故障的仿真生产技术栈完成分流、缓解与彻底解决；讲师风格随学员进步从"主驾"退到教练，最终成为"旁观指导者"。

**走上轮值岗位（Going On-Call）三门课**：轮值基础（On-Call Basics）→ Google 应急事件管理（IMAG）与事故通报 → 轮值升级机制（On-Call Escalations）；采用自导式（self-paced）、与具体服务无关（service-agnostic）的设计，由各团队自行补充服务专属细节。

**入门项目的六个特征**：对团队和/或业务有用；自包含（边界清晰、独立成体系）；可在合理时间窗口交付；不具有过强的时间紧迫性；对团队而言很重要；不在该服务的关键路径上。同时为新人指定专属导师（mentor）。

**非正式学习五件套**：导师指导（Mentoring）、影子跟随与反向影子跟随、模拟演练（厄运之轮）、逆向工程（用调试与监控工具从底层原理理解系统）、研读事后总结——都是低成本、可扩展的持续学习途径。

## 实践要点

- [ ] 按 SRE-SWE / SRE-SE 双画像设计不同面试组合，用特雷诺曲线校准混合型人才
- [ ] 持续监控端到端招聘时长；超过约 40 天先优化流程，而非单纯加大招聘投放
- [ ] 管理岗候选人与 IC 走完全相同的技术面试，另加领导力专项考察
- [ ] 校招从大一大二实习切入：低门槛 + 真实分布式系统实操 + 实习导师（host）/新人导师（mentor）
- [ ] 新人必配导师与入门项目（自包含、不在关键路径、无过强时限），拒绝自生自灭
- [ ] 用轮值值班学习清单界定上岗前必须掌握的技术与核心概念
- [ ] 写培训目标只用"学员应能够……"式行为动词；对目标无贡献的幻灯片与文档坚决删
- [ ] 用 ADDIE 组织课程开发，并指定 SME 持续维护内容时效
- [ ] 把培训当生产服务运营：自助化交付、监控完成率与 NPS、自动化行政琐事以实现亚线性扩展
- [ ] 用灵活轮值机制（缩短班次、双人分担、紧急换班、可审批免轮值）化解最常被提及的流失诱因
